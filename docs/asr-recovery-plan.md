## 目標與使用情境

- ASR 無法連線、暫時斷線或辨識逾時時，繼續錄音並保留未完成工作。
- 使用者可隨時看見哪些會議正在辨識、還欠多少音訊、為何等待及何時重試。
- 使用者可暫停、立即重試、取消、刪除補辨識任務，或停止某場會議自動補辨識。
- 切換頁面不影響工作；整個程式關閉後不執行，重開後恢復符合條件的工作。
- 人工暫停、取消、刪除及停止自動補辨識的選擇也須持久化。
- 不自動刪除原始錄音，不重複寫入逐字稿，不將人工刪除的任務重新建立。

## 0.3.45 起點的缺口（以下由本次實作取代）

- `transport/transcription/session.ts` 的 HTTP 分段佇列只在記憶體中，最多四段；失敗會清空。
- HTTP 即時分段請求等待上限為 30 秒；WebSocket 初始化等待上限為 20 秒。
- `desktop/ipc/imports.ts` 的背景工作存於 Map，可跨頁面重載，但不會跨程式重啟恢復。
- `persistence/store.ts` 啟動恢復只把進行中的會議標示為 interrupted，不會續跑 ASR 任務。
- HTTP 請求目前只丟出錯誤字串，尚未保留供排程判斷的結構化狀態碼與 Retry-After。
- 單次 HTTP 請求預設等待 180 秒，但目前音檔辨識呼叫端實際指定每段最多 30 分鐘。

## 使用者可見的任務面板

每個專案的總覽頁提供「辨識任務」區塊與任務數量，只列出該專案的任務；側欄不設獨立入口。會議內也顯示該會議的任務摘要，管理入口返回所屬專案總覽。
全域面板可依專案、會議、來源與狀態篩選；大量任務需分頁讀取，不能一次載入全部。

每個任務顯示：

- 專案、會議、錄音名稱，及音訊時間範圍，例如 12:30–13:00。
- 任務來源：即時辨識、斷線補辨識、手動會後補辨識或匯入音檔。
- 狀態、完成段數、待辨識音訊長度、最後失敗原因與實際嘗試次數。
- 等待重試時顯示下一次時間與倒數；設定有問題時提供前往設定的入口。
- 即時服務連線狀態與背景補辨識狀態分開呈現。

範例：

> 錄音持續中 · 即時服務無法連線 · 20 秒後重試
>
> 產品週會 · 待補辨識 3 段，共 45 秒
>
> [暫停背景補辨識] [立即重試] [管理任務]

面板操作規則：

| 操作 | 行為 |
| --- | --- |
| 暫停任務 | 停止排程；執行中的請求發出取消，保留分段與進度，之後可繼續 |
| 暫停全部背景任務 | 停止背景補辨識與匯入工作；錄音及即時辨識繼續 |
| 繼續 | 僅恢復使用者選取的工作；不順帶恢復其他已暫停的任務 |
| 立即重試 | 發起一次共用服務探測；不能突破服務端 Retry-After 的等待期限 |
| 取消任務 | 停止該任務並保留可見的已取消紀錄，後續不自動重試 |
| 刪除任務 | 從待處理清單移除；保留原始錄音與已完成逐字稿 |
| 停止此會議自動補辨識 | 停止新建該會議的背景補辨識工作；已存在的工作可由使用者另行批次取消或刪除 |
| 重新建立會後補辨識 | 使用者明確選取錄音與範圍後建立新工作，不默默復活舊工作 |

支援多選後批次暫停、繼續、取消與刪除，摘要顯示受影響的會議、任務數及音訊長度。
任務刪除與錄音檔刪除是分開的功能，不能共用模糊的「刪除」操作。
執行中的任務取消或刪除後，晚到的服務結果必須被拒絕，不能再更新逐字稿。
取消或刪除時，既有已完成分段保留，並清楚顯示部分完成及尚未辨識的範圍。
若使用者要重新辨識已完成範圍，先顯示替換範圍，不直接追加一份重複文字。

## 重試政策

### 錯誤分類

| 原因 | 首版處理方式 |
| --- | --- |
| DNS 暫時失敗、拒絕連線、網路中斷、連線重設 | 自動重試連線，保留待辨識音訊 |
| 連線或初始化逾時 | 依服務共用退避排程重連 |
| HTTP 408、429、500、502、503、504 | 視為可重試；供應商明確回報永久額度不足則轉為需處理 |
| 辨識回應逾時 | 保留相同分段與識別碼，有限次重試；避免每次重做整段錄音 |
| 401、403、模型或端點不存在、無效設定 | 暫停受影響任務並顯示需處理；修正相同服務設定後可重新測試 |
| 無效憑證、主機名稱不符、格式不支援、損壞音檔 | 不盲目重試；提示修正設定或檔案 |
| 使用者暫停、取消或刪除 | 不自動重試，也不計入服務失敗次數 |

先以具體錯誤代碼、HTTP 狀態與協定錯誤分類，不以訊息字串比對作為主要判斷。
未知錯誤採有限重試後需處理，避免永久錯誤造成無限請求。

### 服務連線重試

- 首次立即嘗試，失敗後等待 2、5、10、20、40、60 秒，此後最多每 60 秒一次。
- 每次加入約 ±20% 隨機差距，避免多個客戶端同時重連。
- 同一服務設定共用失敗狀態與下次嘗試時間，同時只容許一個探測，不能每個分段各自重連。
- 持續離線不把整個佇列逐段標為失敗，也不消耗所有待處理分段的重試額度。
- 有正在錄音或可執行的待處理任務時才重連；全部被人工暫停或取消後停止背景探測。
- 偵測到網路恢復或使用者點「立即重試」時，可提前進行一次共用探測；仍遵守服務端等待期限。
- 長時間停用後只發一個探測，不補發休眠期間漏掉的計時器。
- 服務穩定完成一個請求或有效辨識回合後才重設失敗次數，不能只因 TCP 接上就重設。
- 網路恢復事件只是提示，實際請求成功才視為服務恢復。

### 回應逾時與流量限制

- 同一音訊分段最多六次實際辨識失敗，之後標示需處理，保留音訊供人工重試或刪除。
- 實際嘗試次數與可重試失敗次數分開保存；取消、等待服務及離線探測不消耗分段失敗額度。
- HTTP 有有效 Retry-After 時，下一次時間不得早於該期限；支援秒數與 HTTP 日期。
- 無效或已過期的 Retry-After 改採本地退避，不提早繞過有效的遠期等待時間。
- 首版每個服務只執行一個背景辨識請求；即時流量優先，避免補辨識壓垮剛恢復的服務。
- 不自動切換到其他廠商或不同服務端點；修正金鑰可延用同服務任務，切換服務需明確指定。
- 超時參數區分連線、即時 HTTP 分段與背景分段，沿用既有有效設定作為遷移基準。

## 持久化與生命週期

### 分段落盤

1. 將待辨識音訊寫成可獨立解碼的分段，完成寫入與同步後，再登記為 queued。
2. 以暫存檔、原子改名及資料庫交易降低半寫入風險；啟動時掃描並修復未完成提交。
3. 分段可以是 PCM/WAV；不能假設 MediaRecorder 每次產生的 WebM blob 都能獨立解碼。
4. 原始會議錄音仍獨立保存；即時辨識傳輸不阻塞錄音寫入。
5. 首版落盤分段保證已提交範圍可恢復；突然斷電時尚未提交的尾端仍可能中斷，不宣稱零遺失。

### 資料模型與排程

新增專責 ASR repository，使用既有 SQLite 資料庫與具型別的資料契約，避免膨脹 Store。

- 任務：id、meetingId、recordingId、來源、建立與更新時間、狀態及人工控制旗標。
- 分段：穩定識別碼、順序、音訊範圍、檔案路徑、校驗資訊、完成結果及套用狀態。
- 重試：服務設定識別、實際嘗試次數、失敗次數、nextAttemptAt、結構化且已遮罩的最後錯誤。
- 執行控制：租約、執行世代、取消標記、父任務狀態及待清理檔案。
- 人工排除：使用者刪除或取消的範圍，以及會議自動補辨識的啟用狀態。
- 任務資料不保存明文金鑰；使用現有加密設定取得憑證，記錄錯誤前遮罩敏感資訊。

狀態：queued、running、waiting_retry、paused、needs_attention、completed、cancelled。
刪除任務可隱藏於一般列表，但保留必要的取消與範圍標記，防止恢復程序重新建立。
排程器在主程序執行，採資料庫 nextAttemptAt 選取工作，不能只靠 renderer 計時器。
同一會議依音訊時間合併結果，不依網路回傳先後追加。
不同會議公平排程；需人工處理的單一分段不能永久阻塞其他會議。

### 成功、重啟與取消

- 使用穩定分段 ID 更新逐字稿；結果套用與任務完成標記在同一 SQLite 交易中提交。
- 先落盤辨識結果再執行提交，啟動時可補完未提交結果，不重複發送已成功的請求。
- 程式重啟後回收舊租約；running 回到 queued，保留 nextAttemptAt，不清空重試歷史。
- paused、cancelled、已刪除與停止自動補辨識的工作，不因重啟或修正設定而自動恢復。
- 重啟只恢復既有背景任務，不自行打開播放裝置、麥克風或建立新錄音。
- 暫停、取消與刪除先持久化控制狀態，再取消網路請求；套用結果前再次核對執行世代。
- 清理工作須等請求停止並確認分段沒有其他引用，才刪除任務擁有的暫存檔。
- 原始錄音不隨任務清理；未完成分段不因一般完成歷史保留期限被刪除。
- 刪除會議時先停止其全部 ASR 任務，再沿用既有會議資料清理流程。
- 本機可保證同一結果只套用一次；遠端 timeout 後重送可能已在供應商端執行，不能保證不重複計費。
- 僅在供應商明確支援時傳送冪等識別碼，不假設所有 ASR 服務都有相同能力。

## Realtime 與背景補辨識的分工

- HTTP 即時分段使用相同的持久化佇列，連線失敗後仍保留分段，不再因四段上限清空工作。
- WebSocket 斷線後建立新的 session，WebRTC 需重建連線、協商與資料通道，不能只重送舊 offer。
- Realtime 重連成功後優先處理新音訊；斷線缺口以已設定的 HTTP 音檔服務在背景補辨識。
- 缺口範圍依本地音訊時間與已完成結果判定，不使用 WebSocket 連線開始時間取代會議時間。
- 部分結果與時間不精確時保守保留缺口，使用分段來源及覆蓋範圍合併，避免刪掉已確認文字。
- 沒有可用的補辨識服務時標示需設定並保留音訊，不宣稱缺口已經恢復。
- 沒有人聲或尚未達到提交條件時，不因沒有文字就判定 timeout；針對已提交的有聲回合判斷停滯。
- 使用者刪除缺口工作後不自動重建；若繼續錄音，只有新範圍依該會議的自動補辨識設定處理。

## 容量與顯示

- 磁碟保存分段，記憶體只保留有限寫入緩衝與目前處理段；列表和排程查詢都分頁。
- 首版暫存音訊容量預設上限 2 GB；剩餘磁碟低於 1 GB 時提示並暫停新增補辨識分段。
- 達到容量上限時顯示受影響範圍，不靜默刪除未辨識音訊；原始錄音能寫入時繼續錄音。
- 原始錄音也無法寫入時，明確停止錄音並說明最後成功保存的位置。
- 程式關閉時保留任務與檔案；在面板提示關閉期間不會執行，重新開啟後可繼續。
- 全域狀態摘要不連續彈出相同錯誤；服務狀態或需處理事項改變時才提示。

## 實作順序與驗收

1. 結構化錯誤與共用退避政策：可重試分類、Retry-After、取消與測試用虛擬時鐘。
2. ASR repository、分段落盤、租約與恢復：交易一致性、穩定 ID、清理與人工排除標記。
3. HTTP 即時／音檔工作接入佇列，同步交付可見的任務列表與暫停、取消、刪除。
4. WebSocket／WebRTC 重連及缺口補辨識、停止自動補辨識與全域控制。
5. 回歸測試、封裝測試與版本建置；各階段遵守檔案 500 行、目錄容量及嚴格型別規則。

必要測試：

- 服務未啟動，錄音後啟動服務；驗證重連、補辨識、範圍順序與任務狀態。
- 請求逾時但遠端可能成功、斷網、429/503 等待時間、永久錯誤及設定修正。
- WebSocket 斷線、WebRTC 重建、靜音時不誤報、時鐘／休眠與網路恢復事件。
- 落盤、結果保存、資料庫提交與清理各階段中斷，再啟動後不遺失已提交工作或重複文字。
- 排隊／執行／等待重試時人工暫停、取消、刪除，晚到結果不再更新文件。
- 批次刪除後不復活、重啟後仍暫停、停止自動補辨識後不新增缺口工作。
- 修改設定或按立即重試不解除其他任務的人工暫停，也不突破 Retry-After。
- 長會議、多會議、磁碟容量不足、分段引用清理與原始錄音保護。
- 全域／會議篩選、進度與倒數、鍵盤操作、窄視窗、完整檢查及封裝版驗證。

## 協定依據

- [RFC 9110 §10.2.3 Retry-After](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3)：支援秒數與 HTTP 日期。
- [RFC 6585 §4](https://www.rfc-editor.org/rfc/rfc6585.html#section-4)：429 可附 Retry-After。
- [OpenAI Realtime transcription](https://developers.openai.com/api/docs/guides/realtime-transcription)：依 committed item_id 關聯音訊，完成回合允許亂序回傳。
